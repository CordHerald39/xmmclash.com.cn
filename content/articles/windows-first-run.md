## 本文到底教哪个“小猫咪”

“小猫咪 Clash”不是一个唯一的软件名称。本文具体对象是 Clash Verge Rev 的 Windows 版本，其他客户端只能参考检查逻辑，不能照搬按钮。2026-09-19 核对开发者发行页时，v2.5.2 提供 x64 与 arm64 安装器；这是固定版本举例，不代表以后一直是最新版。

## 1. 先选对架构与安装器

在 Windows 设置 → 系统 → 系统信息查看系统类型。Intel / AMD 的 x64 Windows 对应 x64；Windows on ARM 对应 arm64。下载页的 aarch64.dmg 是 macOS 文件，不能因为也写 ARM 就下载到 Windows。

| v2.5.2 文件示例 | 用途 |
| --- | --- |
| Clash.Verge_2.5.2_x64-setup.exe | Windows x64 安装器 |
| Clash.Verge_2.5.2_arm64-setup.exe | Windows ARM64 安装器 |
| 含 fixed_webview2 的安装器 | 项目提供的内置 WebView2 版本，按官方故障说明选择 |
| .sig | 配套签名文件，本身不是安装程序 |

安装器与说明均从[开发者 v2.5.2 发行页](https://github.com/clash-verge-rev/clash-verge-rev/releases/tag/v2.5.2)取得。安装后记录关于页版本；下载页版本和实际运行版本不一致时，先检查是否打开了旧快捷方式。

## 2. 添加订阅后确认当前配置

打开订阅页面，粘贴服务方提供的适配地址并导入。导入成功后主动选择该配置，再到代理页面选择策略组中的节点。保留原有配置，第一次先不添加复杂合并脚本。成功标准是当前配置明确、节点可选择、日志没有持续出现配置解析失败。

若导入失败，先看错误属于下载还是解析。返回登录网页与 YAML 格式错误的解决方法不同；不要把订阅地址公开到评论或截图里。

## 3. 先完成系统代理路径

按官方快速入门开启系统代理，记录客户端显示的本地端口。Windows 设置 → 网络和 Internet → 代理中的地址和端口应与客户端对应。先保持 TUN 关闭，以便知道首次验证的是哪一条路径。

使用浏览器打开固定测试地址，同时查看客户端连接记录。验收至少包括目标域名、策略出口和请求时间三项。页面能打开但没有对应记录时，可能发生绕过、缓存或应用自有代理，需要重新建立请求，不能直接记为代理成功。

## 4. 为什么命令行结果可能不同

部分命令行工具不会自动读取浏览器使用的系统代理。需要测试端口时，可用 curl.exe 的显式 --proxy 参数；不要把示例端口直接当成你的默认端口。

本站在独立 Mihomo v1.19.31 环境中，使用 18790 混合端口和 18791 本地测试服务，实际得到 HTTP 与 SOCKS5 返回相同测试正文的结果。该实验验证显式代理链路，不等于已操作 Clash Verge Rev 的安装器或系统代理开关。

## 5. 退出也要验收

先在客户端关闭系统代理，再正常退出。检查 Windows 代理页是否仍指向已停止的本地端口，并确认日常直连页面可用。若异常退出后网络受影响，按[恢复网络教程](/articles/restore-network/)检查，不先执行全局网络重置。
