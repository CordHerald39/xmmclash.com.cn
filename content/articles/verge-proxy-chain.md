链式代理需要前一跳能够连接下一跳。电脑自己能访问某个代理地址，不代表远端入口也能访问它。搭建前先画清楚“设备 → 入口 → 出口 → 目标”的路径，比反复调整节点排列更有效。

## 核对客户端和版本

本文指 Clash Verge Rev。2026-10-04 查阅的官方链式代理文档要求 v2.4.5 或更高版本，界面通过 Mihomo 的 `dialer-proxy` 实现链路。旧版本找不到对应操作时，不要照着其他客户端截图猜菜单。

先分别确认入口和出口的协议、地址、端口与认证方式。出口应是你有权使用的代理，不是仅凭 IP 就能转发请求的普通主机。

## 地址从哪一端访问

| 地址类型 | 必须回答的问题 |
| --- | --- |
| `127.0.0.1` | 它是连接发起端自身，不是自动指向你的电脑 |
| `192.168.x.x` 等私网地址 | 前一跳是否确实处于能到达该私网的网络中 |
| 公网域名 | 下一跳服务是否监听、允许前一跳访问，认证是否正确 |

例如入口在远端，出口却填了家中局域网地址，不能仅凭本机可以访问家庭设备就认定链路可用。应先解决前一跳到出口的可达性，不为测试随意把家中代理开放给整个互联网。

## 按官方界面建立两跳

1. 备份当前配置。右键订阅配置，选择“编辑节点”。
2. 按实际服务信息添加所需节点。官方文档支持 HTTP、SOCKS 和内核支持的其他节点 URI。
3. 按预期顺序把节点加入代理链：最上方是入口，最下方是出口；初次试验先用两跳。
4. 核对名称及认证信息。URI 中的用户名或密码包含特殊字符时，按 URI 规则编码，不能直接让 `@` 等字符改变地址解析。
5. 应用配置并选择链路，重新建立目标请求。

节点编辑层能保留自定义配置，不应为了加链路直接覆盖服务方订阅原文。不要把含用户名、密码的 URI 截图分享。

## 用分段结果定位失败

先验证入口单独可用，出口在其预期网络内可用，再验证两跳链路。出口从本机直连失败不一定证明出口服务坏了；它可能本来只允许入口网络访问。测试结果要注明发起端。

链路失败时检查下一跳可达性、认证和日志中第一条相关错误。若入口与出口分别可用，但组合失败，优先检查顺序及前一跳到下一跳的路径，而不是再加入第三跳。

两跳访问成功后，可用同一个出口核对目标请求，但出口 IP 观察只能说明该次请求所走的出口，不能证明所有应用都使用了代理链。多跳也不保证更快或匿名；每一段都增加依赖，应按实际需求决定是否保留。

## 退出试验

恢复原先节点选择和配置，再确认目标应用及基础网络正常。保留不含凭据的节点代号、链路顺序和故障日志，便于之后复核。
