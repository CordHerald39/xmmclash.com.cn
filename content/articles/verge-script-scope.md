有多个配置时，全局扩展脚本会处理不同订阅。若只想对某一份配置修改一个选项，需要限制作用范围。本文面向 Clash Verge Rev，不适用于名称相似的其他 Clash 客户端。

## 先选作用范围，再写条件

如果改动永远只属于一个订阅，可以直接使用该订阅的扩展脚本。只有希望集中管理多份订阅的差异时，再考虑在全局脚本中按名称判断。这样可以减少不必要的条件分支。

官方文档说明脚本入口为 `main`，接收配置对象 `config`，返回处理后的对象。v1.7.3 起增加 `profileName` 字符串参数，表示当前处理的配置文件名；应以当前客户端传入的实际名称核对，不把节点名或策略组名当成它。

## 一个能说明边界的最小脚本

以下是教学示例。先把 `工作配置` 改成你已核对的配置名称，再决定该设置是否符合需求；它不包含节点或订阅地址。

```javascript
function main(config, profileName) {
  if (profileName === "工作配置") {
    config["tcp-concurrent"] = false;
  }
  return config;
}
```

这里的比较是精确字符串比较。多了空格、大小写不同或重命名，都可能使条件不成立。每条执行路径都返回配置，避免在不匹配时漏写返回值。这个例子只验证作用域，不承诺网络性能变化。

## 脚本不是浏览器或 Node.js 程序

截至 2026-10-04 的官方说明，扩展脚本使用 JavaScript 执行器，提供部分基本对象、数组、JSON、正则等 API，并明确不支持网络 IO 和文件 IO。

因此，不能把依赖 `fetch` 下载订阅、读取本地文件或操作网页 DOM 的代码直接粘贴进去。`config` 是 YAML 转换后的对象，不是 YAML 文本；需要处理数组时先确认属性实际为数组，处理对象时先检查是否存在。

脚本也不能让应用接管的设置绕开最终回写。若最终配置未采用期望值，先检查作用域、执行日志、后续订阅扩展及设置页面，不把所有未生效情况都归为语法错误。

## 按两个订阅验收

1. 备份旧脚本，确认新代码所在层级及目标配置名称。
2. 激活目标配置并重新应用，检查脚本日志和最终 `tcp-concurrent` 值。
3. 激活另一份配置，确认它的原值未被这条条件改写。
4. 将目标配置临时改名或核对其真实名称时，重新检查条件匹配。恢复原名后再应用。
5. 发生错误时恢复旧脚本，保留错误行及执行对象，避免直接覆盖全部配置。

验收应分别记录“脚本执行完成”和“最终配置正确”。没有异常弹窗不等于条件匹配成功；原值本来相同也不足以证明改动执行过。
